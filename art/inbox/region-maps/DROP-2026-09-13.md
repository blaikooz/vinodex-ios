unchanged at 30, produced a `globe-index.png` whose pixels are identical to the
copy in this folder — 0 differing cells out of 2,097,152. The gz round-trip
costs nothing. (The two files' *bytes* differ; that is the PNG encoder, not the
content. Same for `rgn-italy.png`: 0 differing cells, different bytes.)

## 2. What shipping the source turned up: France

`fr-departements.json` held **96** units. A fresh extract gives **101** —
Natural Earth files Guadeloupe, Guyane française, La Réunion, Martinique and
Mayotte under `admin='France'`. The committed file had been hand-cut before
`extract_admin1.py` existed.

Geometry on all 96 shared units was byte-identical, so nothing looked wrong.
But the failure mode is bad and silent: regenerate that file and France's
bounding box runs from the Channel to Réunion, every `subject_rect` in the
manifest goes wrong at once, and **no assert in the pipeline fires**. The map
just comes out as a speck in an ocean.

The fix is not to keep the hand-cut file. It is to put the decision where the
pipeline can see it:

```python
exclude=['Guadeloupe', 'Guyane française', 'La Réunion', 'Martinique', 'Mayotte'],
```

**Verified in two steps.** Added the `exclude` against the old 96-unit file →
all 146 rendered outputs byte-identical. Then regenerated `fr-departements.json`
in full from `ne-admin1.json.gz` (101 units, now with the `region` column the
other eight extracts carry) → all 146 outputs **still** byte-identical.

`fr-departements.json` in this drop is the regenerated one.

### New gate: `verify_extracts.py`

Regenerates every committed admin-1 extract from source and compares bytes. This
is what caught France, and it is what stops the hand-cut version coming back.

```
fr-departements.json   ok    101 units, 5 excluded by config
it-provinces.json      ok    110 units, 0 excluded by config
es-provinces.json      ok     52 units, 4 excluded by config
pt-districts.json      ok     20 units, 2 excluded by config
```

means the file and the source disagree and someone has to say which is right.
The script prints the unit-name delta so that call is quick.

This belongs in CI next to the other Python gates, if you are adding them.

## 4. Three bugs found on the way, two fixed and one reported

### 4a. Running `globe_tex.py` destroyed `globe-meta.json`. Fixed.

`globe-meta.json` is installed **verbatim** by `install_globe.py` and decoded by
`GlobeIndex.Meta.Entry`, which requires `idx`, `admin`, `label` and `mapped`,
all non-optional. `install_globe.py` additionally requires `fill`.

`globe_tex.py` emitted `idx`, `admin`, `stem`. Nothing else. Four fields had
been added to the shipped file by hand at some point, and **regenerating the
globe would have stripped them** — `KeyError: 'fill'` at install, and past that
a `GlobeIndex(meta:)` that returns nil and a sphere that goes back to
untappable. No test catches it, because the file is data. This is the same shape
as the `france_rect` → `subject_rect` rename, and I nearly shipped it: my first
staged `globe-meta.json` was the stripped one.

The generator now emits the whole contract and **carries forward anything it
does not compute** from the file already on disk, so authored fills stay
authored. It asserts every field is present and that no two countries share a
fill, at generate time rather than on a device. The two derived fields, for the
record:

- `key` is the flat-map directory, `stem` is the app slug. They differ exactly
  once: stem `new-zealand`, key `newzealand`.
- `label` is `admin` uppercased, with one override — `United States of America`
  → `UNITED STATES`.

**Also new: `index_sha256`** at the top level of `globe-meta.json`, checked by
`install_globe.py`. `idx` is a position in an alphabetical list, so adding a
country renumbers most of them, and a raster from before pairs *cleanly* with a
meta from after — every country answers as its alphabetical neighbour. No crash,
no failing shape, and it reads as "the hit test is off" rather than "two files
disagree". Verified in both directions: correct pair installs, corrupted hash
exits with a message naming the fix. Swift ignores the extra key.

### 4b. `brighten()` collapses the country palette on screen. Reported, not fixed.

`install_globe.py` lifts each fill with `v = min(1.0, v * 2.05)` before it
reaches the sphere. **That clip is doing real damage**: every fill above v≈0.49
lands on the same value, so colours that are far apart in the manifest arrive at
the glass as one. Measured on the 30 authored fills, in CIELab, after
`brighten`:

| pair | ΔE authored | ΔE as shipped |
|---|---|---|
| portugal / united-kingdom | 25.5 | **2.6** |
| slovenia / usa | 18.7 | **4.5** |
| chile / georgia | 15.3 | **4.9** |
| hungary / italy | 16.6 | **5.6** |
| argentina / germany | 20.9 | **6.3** |
| croatia / india | 19.4 | **6.9** |

This predates the drop and I have not touched it — changing it restyles all 30
countries and that is Harrison's call, not mine. What I measured for the
alternatives, if you want them:

| transform | worst pair | 4th worst | mean value |
|---|---|---|---|
| `min(1, v * 2.05)` (shipped) | 2.6 | 5.6 | 1.00 |
| `v + (1 - v) * 0.40` | **7.7** | 8.2 | 0.79 |
| `v + (1 - v) * 0.60` | 5.6 | 6.0 | 0.86 |

A non-clipping lift roughly triples the worst pair and costs visible brightness.
It does not solve it: portugal `#277C63` and united-kingdom `#3DA485` are close
in hue *and* chroma, so the real fix is re-authoring about six of the thirty
against the shipped transform. Say the word and I will.

What I did do is stop the new ten inheriting the problem. `brighten` now lives
in `palette.py` as the single definition (`install_globe.py` imports it), and
the new fills were **chosen in post-brighten space**. Chosen in the authored
space the first pass scored ΔE 15.5 and shipped at 1.7. Chosen correctly the
four clear **ΔE 30.9 against all 33 others as shipped**, better than any pair in
the authored thirty.

Two weaker objectives were tried and measured before the one that shipped, and
both are written into the code so nobody re-derives them:

- adjacency, the rule the flat maps use → Slovakia and Turkey at ΔE 6.6. They do
  not touch. A flat map shows one country; a globe shows a hemisphere.
- within 40° of centroid → China and Turkey at ΔE 4.0. Their centroids are 45°
  apart and they are still in the same eyeful. Any threshold has an outside, and
  the outside is visible.

The rule that shipped is the complete graph: every country unlike every other.

### 4c. `region_check.py <country>` destroyed the region index. Fixed.

Found by running the gate and then looking at `git status`, which is the only
reason I saw it at all.

The seven older countries carry two pin files. `pins-<c>.json` is dense and
name-only — more coverage, better at catching a mis-painted département.
`pins-<c>-catalog.json` is the real `regions.ts` rows, with catalog ids. The
default invocation, the one in the script's own docstring, uses the dense file.

At the end of the run:

```python
by_id[i or n] = g        # i is the pin's catalog id, n is its name
```

So `python3 region_check.py france` replaced an index keyed `R001 → bordeaux`
with one keyed `Medoc → bordeaux`. The gate still printed PASS. The docstring
still said `id` "is optional and only used in the report" — it is not; it keys
the artefact the app reads to turn a catalog row into a painted region. Nothing
failed anywhere. The file just quietly stopped being able to answer the question
it exists for, and the next commit would have carried it.

The check and the index are now separate jobs. The check runs on whatever you
name it; the index is written from whichever pins carry ids — the catalog file
for those seven, the single file for Austria and China — and a run whose pins
have no ids **writes nothing and says so**, because leaving a good index alone
beats replacing it with a worse one. An assert catches an id-less row reaching
the index.

**Verified:** all nine regenerate byte-identical to the committed files, from
the correct source in each case, on this machine and on the mini.

I restored the two files I had already dirtied (`out/france`, `out/italy`) from
`HEAD` before staging anything.

  assert in `globe_tex.py` is a proxy for it and asks a narrower question:
  it compares against `regions.ts` origins, where the test presumably resolves
  through whatever `GlobeIndex` actually looks up. If those two ever disagree,
  the test is right and my assert needs to learn why.

  about whether a config's `exclude` list is *correct* — only that the extract
  matches source. France's five were correct because I checked the render;
  a future country's will need the same check.
